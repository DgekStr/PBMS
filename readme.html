📊 PBMS Proxmox Backup Monitoring System

Мониторинг VM / LXC и бэкапов в кластере Proxmox с HTML-дашбордом
Проект сервиса подготовлен · focuslens.dev
✅ Работает на Proxmox 7/8 🐚 Bash + Python 📦 Минимум зависимостей 📧 msmtp / Postfix

PBMS — это готовый скрипт для ежедневного автоматического мониторинга состояния виртуальных машин, LXC-контейнеров и их резервных копий в кластере Proxmox.

Скрипт собирает данные через pvesh, сканирует папку бэкапов (/backup/dump), проверяет логи на ошибки, формирует современный HTML-дашборд в стиле FocusLens и отправляет его на электронную почту через msmtp.

🚀 Возможности

🖥️ Мониторинг нод
3 ноды: pve, pve2, pve3. Доступность проверяется через ping + SSH.
📦 VM и LXC
Сбор статуса (running/stopped), имени и ID для всех объектов.
💾 Бэкапы
Дата последнего бэкапа, размер, статус (OK / ERROR / Нет бэкапа).
📊 HTML-дашборд
Стиль FocusLens: карточки статистики, цветовая индикация, адаптив.
📧 Отправка по почте
Через msmtp (как в вашем старом скрипте). Кодировка UTF-8, HTML-письмо.
📋 Логирование
Полный лог в /var/log/pve_backup_monitor.log.

📥 Установка

1. Зависимости

root@pve:~# apt update
root@pve:~# apt install -y python3 jq msmtp

2. Создать скрипт

root@pve:~# nano /usr/local/bin/pve_backup_monitor.sh
# Вставить содержимое скрипта (см. ниже)
root@pve:~# chmod +x /usr/local/bin/pve_backup_monitor.sh

3. Настроить msmtp

Убедитесь, что msmtp настроен для отправки с robot@dgek.ru.

# /etc/msmtprc
account default
host smtp.yandex.ru
port 587
auth on
user robot@dgek.ru
password YOUR_PASSWORD
tls on
tls_starttls on
from robot@dgek.ru

⚙️ Настройка

Все основные параметры задаются в начале скрипта:

# ============================================
# НАСТРОЙКИ
# ============================================

TO_EMAIL="dgekstr@yandex.ru"
FROM_EMAIL="robot@dgek.ru"
NODES="pve pve2 pve3"
BACKUP_DIR="/backup/dump"

Важно: путь BACKUP_DIR должен указывать на папку, где хранятся файлы бэкапов в формате vzdump-qemu-*.vma* или vzdump-lxc-*.tar*.

📋 Структура HTML-отчета

Блок Содержимое
Шапка Название кластера, список нод, дата и время обновления
Статистика Всего VM / LXC, Running / Stopped (цветные карточки)
Таблица Нода · ID · Имя · Тип (VM/LXC) · Статус · Последний бэкап · Размер · Статус бэкапа
Цветовая индикация 🟢 running / OK  ·  🔴 stopped / ERROR  ·  🟠 Нет бэкапа

🔍 Логика проверки бэкапов

  • Для каждой VM ищется самый новый файл vzdump-qemu-{ID}-*.vma*
  • Для каждого LXC — vzdump-lxc-{ID}-*.tar*
  • Если файл найден — извлекаются дата и размер
  • Проверяется .log файл на наличие слов: error, failed, failure, critical, unable
  • Если есть ошибки — статус ERROR, иначе — OK
  • Если файл не найден — Нет бэкапа

📌 Требования к окружению

  • Proxmox VE 7 или 8 (Debian 11/12)
  • Запуск от root (доступ к pvesh и /backup/dump)
  • Установленные пакеты: python3, jq, msmtp
  • Настроенный msmtp для отправки писем
  • Общая папка /backup доступна на всех нодах

🛠️ Устранение проблем

Проблема Решение
pvesh: command not found Запускайте скрипт от root на Proxmox ноде
Нет доступа к /backup/dump Проверьте монтирование: mount | grep backup
Письмо не уходит Проверьте msmtp: echo test | msmtp -t
Нода недоступна Проверьте сеть и SSH: ping pve2, ssh root@pve2
Пустой отчет Проверьте, что в /backup/dump есть файлы vzdump-*
